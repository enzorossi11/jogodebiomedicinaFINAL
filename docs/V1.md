# A Viagem do Alimento — o que é a V1

Contexto completo do trabalho feito sobre o projeto original ([Bsalvo/jogodebiomedicina](https://github.com/Bsalvo/jogodebiomedicina)) até chegar na V1 publicada em https://enzorossi11.github.io/jogodebiomedicinaFINAL/. Serve para quem pegar o projeto daqui para frente entender o que mudou, por que mudou e onde mexer.

## Ponto de partida

O repositório original tinha duas propostas (a Viagem do Alimento e o "Meu corpo está falando comigo"), uma cena Three.js funcional e um roteiro pedagógico bem pensado, mas a experiência não se sustentava:

- A tela era dividida em três barras de navegação empilhadas, chips flutuantes e um dock na base; o modelo 3D ficava pequeno num palco bege enorme.
- Os títulos usavam jargão técnico ("HD-2D", "16-bit", "Three.js") voltado para quem programa, não para quem usa.
- Dentro dos órgãos 3D flutuavam sprites 2D pixelados; as animações eram cosméticas (um anel que muda de cor, uma gota que orbita).
- O repositório carregava arquivos internos de automação (`AGENTS.md`, `ROADMAP.md`, `TASKS.md`, `.agents/`), documentação com caminhos absolutos do Windows, dependências sem uso (Gemini SDK, Express, dotenv) e caminhos de assets que quebrariam fora da raiz do domínio.
- Não havia testes nem publicação.

A decisão foi **concentrar o trabalho na Proposta 1 (digestão)**, mantendo a Proposta 2 como atividade complementar sem reformá-la.

## O que foi feito

### 1. Base do projeto

- `package.json` limpo: nome `viagem-do-alimento`, scripts `dev`, `build` (verificação de tipos + Vite), `preview`, `test` (vitest), `lint`. Saíram Gemini, Express, dotenv, esbuild, tsx e autoprefixer.
- `tsconfig.json` em modo `strict`; `vite.config.ts` com `base` vindo de `BASE_PATH` (necessário para o GitHub Pages), chunks separados para Three.js e a configuração do vitest (jsdom).
- Fonte Lexend hospedada localmente (`@fontsource-variable/lexend`), sem chamada ao Google Fonts.
- Todos os caminhos de assets passam por `import.meta.env.BASE_URL` (`src/data/assetCatalog.ts`), por isso funcionam em `/jogodebiomedicinaFINAL/`.
- Workflow `.github/workflows/deploy.yml`: a cada push na `main` roda os testes, gera o build e publica no GitHub Pages (Source: GitHub Actions).
- Removidos os arquivos internos de automação e a documentação de arquitetura que apontava para máquinas específicas. Ficou `docs/domain/` (regras pedagógicas, glossário, personas), que é conteúdo do projeto.

### 2. Interface

Arquivos novos em `src/components/`:

- **`Cabecalho.tsx`** — um único cabeçalho: logotipo, abas (Início / A viagem / Meu corpo), botão Roteiro, som, menu de acessibilidade (baixo estímulo e tamanho do texto em três níveis) e o botão "Quero uma pausa", sempre visível. No celular vira ícone.
- **`Capa.tsx`** — página inicial focada na viagem: título, escolha do alimento já na primeira dobra, as seis paradas, os compromissos sensoriais e dois cartões secundários (Meu corpo e Roteiro pedagógico).
- **`Jornada.tsx`** — a viagem em si. Substitui o antigo `Proposta1Viagem3D.tsx` mantendo a mesma máquina de estados (fase da mordida, 5 mastigadas, saliva, deglutição com progresso 0–100, 3 anéis do esôfago, 3 gotas gástricas, 3 nutrientes, 3 gotas de água, ordem dos 5 órgãos). Layout: palco 3D ocupando a tela e painel lateral com uma ação principal por parada, trilha de progresso, "Observar sem tocar" (executa a parada sozinho), "Ouvir" (narração), "Repetir esta parada", "Você sabia?" e Voltar / Próxima parada sempre habilitados.
- **`src/data/etapas.ts`** — ordem das etapas, nomes humanos, trilha de progresso e as funções `acertosDaOrdem` / `ordemCompleta` da montagem final.
- **`src/index.css`** — tokens de design em Tailwind v4 (`@theme`): paleta verde-mar (ação), areia (fundos), ameixa (texto), pêssego (destaque); classes `.btn-*`, `.cartao`, `.rotulo`, `.chip`; atributos `data-fonte` e `data-baixo-estimulo` no `<html>` controlam tamanho de texto e cores.
- `App.tsx` reescrito: módulos `capa`, `viagem`, `corpo`; preferências persistidas em `localStorage` (`viagem_do_alimento_prefs_v1`); overlays de pausa, roteiro e legenda mantidos.

### 3. Cena 3D

Em `src/components/three/Proposta1HD2DScene3D.tsx`:

- Câmeras por estação reaproximadas (fov 40, distâncias ~2.1–2.6) para o modelo preencher o palco.
- Renderer com `alpha: true` e fundo transparente; o céu é o gradiente CSS de `.palco-3d`, que também muda no baixo estímulo.
- Mostrador de chão e névoa removidos; piso virou um disco suave translúcido.

As sete estações internas foram refeitas em `src/components/three/stations/` sobre um toolkit novo, **`anatomia.ts`**:

- `TuboDinamico` — tubo ao longo de uma curva cujo raio é recalculado a cada quadro em função da posição e do ângulo. É o que produz peristaltismo, haustros, rugas e o bojo do bolo.
- `Gotas` — gotas com gravidade simples ou que seguem até um alvo.
- `Impulso` — envelope 0→1 disparado quando um contador sobe (uma mastigada, um anel, uma gota).
- `materialMacio` / `materialTranslucido` e a paleta `COR` / `ALIMENTO`.

O que cada estação faz:

| Estação | Arquivo | O que acontece |
| --- | --- | --- |
| Boca | `MouthStation.ts` | Maxilar fixo, mandíbula que desce e sobe a cada mastigada (com ranger lateral), língua, palato, úvula. O pedaço do alimento é amassado, encolhe, vira migalhas e forma o bolo. Saliva cai das glândulas nas bochechas. |
| Garganta | `SwallowStation.ts` | Corte lateral: faringe, epiglote que tampa a traqueia, esôfago com onda, palato mole. Bolhas de ar sobem pela traqueia e param enquanto a epiglote está fechada. |
| Esôfago | `EsophagusStation.ts` | Tubo muscular com fibras; cada anel dispara uma onda peristáltica que aperta atrás do bolo e abre na frente. |
| Estômago | `StomachStation.ts` | Bolsa em J translúcida com rugas, esôfago chegando pelo cárdia. Glândulas pingam, nível de suco sobe, bolo se desfaz em partículas; no fim uma onda leva tudo ao piloro. |
| Intestino delgado | `SmallIntestineStation.ts` | Calha inclinada com 160 vilosidades instanciadas balançando. Nutriente absorvido entra por uma vilosidade e vira um ponto correndo pela artéria. |
| Intestino grosso | `LargeIntestineStation.ts` | Moldura do cólon com haustros e tênia. Água atravessa a parede e segue pela veia; o conteúdo escurece e fica fosco. |
| Caminho completo | `FinalDioramaStation.ts` | Cada órgão entra deslizando para o lugar no tronco; com a ordem completa, um bolinho percorre todo o trajeto em loop. |

`FoodSelectStation.ts` e `FirstBiteStation.ts` (mesa, personagem e prato) foram mantidos.

Regras sensoriais respeitadas em todas: nada pisca, nenhum movimento é brusco, o modo baixo estímulo reduz velocidade e quantidade de partículas (uma gota por vez).

### 4. Testes e documentação

- `src/data/etapas.test.ts` (vitest): ordem das etapas, integridade da trilha, contagem de acertos sem punição, conteúdo pedagógico (um "Você sabia?" por alimento, cinco paradas no roteiro).
- `README.md` reescrito como capa do projeto, com prints em `docs/prints/`.

## Como continuar

```bash
npm install
npm run dev      # desenvolvimento
npm test         # testes
npm run build    # tipos + build
```

Push na `main` publica sozinho. Para testar o build com o mesmo caminho do Pages: `BASE_PATH=/jogodebiomedicinaFINAL/ npm run build && BASE_PATH=/jogodebiomedicinaFINAL/ npm run preview`.

Onde mexer para cada tipo de mudança:

- Texto de uma parada (nome, resumo, rótulo do botão): `src/data/etapas.ts`. Narração e "Você sabia?": `src/data/scriptData.ts`.
- Comportamento de uma parada (quantas mastigadas, o que o botão faz): `src/components/Jornada.tsx`.
- Visual ou animação de um órgão: o arquivo da estação em `src/components/three/stations/`. A função `update(cur, dt, simTime)` recebe o estado atual e o tempo; cada estação só lê, nunca altera o estado.
- Enquadramento: `STAGE_CAMERAS` em `Proposta1HD2DScene3D.tsx`.
- Cores e tipografia: `src/index.css`.

## O que ficou de fora (candidatos para a V2)

- A atividade "Meu corpo está falando comigo" (`Proposta2Interocepcao.tsx` e `BodyInteroceptionScene3D.tsx`) continua com a interface antiga, apenas encaixada no novo layout.
- Os órgãos são geometria procedural ("anatomia de livro infantil"). O próximo salto de qualidade seria usar modelos GLB (por exemplo do Z-Anatomy, licença CC BY-SA) encaixados no mesmo esqueleto de animação.
- No celular o palco 3D fica acima do painel e a página rola; pode valer fixar o palco no topo.
- Não há narração própria gravada; a leitura usa a voz do sistema (Web Speech API), que varia por aparelho.
